MORE BRATS — CUMULATIVE CHANGELOG
Author: Tsoxer
Current release: v1.1.0 — 11-16-2026

Entries are chronological. Test status describes the evidence available for
each release; later results are identified separately. Automated simulations
have never constituted Skyrim gameplay verification. Dates use MM-DD-YYYY.

v0.1 — 11-15-2026
Initial Whiterun proof of concept
- Added one generic Nord child named Child, using male/female vanilla traits
  templates and three vanilla child outfits per gender.
- Used six fixed reusable references, a daily appearance cycle, daytime sandbox
  areas, a Bannered Mare evening routine, and visibility-aware nighttime removal.
- Used vanilla assets, native AI, a quest controller, and compiled Papyrus,
  without SKSE or a third-party gameplay framework.
- Arrival was conservative: an interior transition or leaving the city could
  be needed. Initial checks were structural and mocked; Tsoxer subsequently
  confirmed appearance, outfit randomization, inn entry, and safe removal.
- Gameplay exposed overly stationary daytime behavior near the Gildergreen.

v0.2 — 11-15-2026
Whiterun population and roaming expansion
- Expanded the daily target to 3–6 independently randomized children, using
  36 reusable references for six gender/outfit combinations.
- Added broader road destinations and independent travel/pause behavior instead
  of relying on a few long sandbox periods. Extended daily spawn distribution.
- Kept the 8 AM / 7 PM / 3 AM lifecycle and generic child identities.
- Actual playtesting subsequently exposed spawning, scheduling, and upgrade
  regressions. This release was not a confirmed reliable gameplay baseline.

v0.2.1 — 11-15-2026
Startup, migration, and population recovery work
- Added startup/migration/recovery fixes, stable-ID reference recovery, and
  multi-NPC saved-state checks while preserving earlier identities and fields.
- Investigated quest initialization, aliases, bindings, pending arrivals, and
  adoption of actors already present in older saves.
- Existing-save migration was not established as the sole cause: subsequent
  tests on a pre-mod save still produced no children after an overnight wait.

v0.2.2 — 11-15-2026
Initialization and runtime diagnostics
- Restored the safe interior-arrival path before requiring exterior world data.
  A missing worldspace query could otherwise reject all outdoor destinations.
- Bound pool actors, roads, and legacy targets directly in quest VMAD, retaining
  FormLists and stable-ID fallbacks for saved properties. Individual missing
  dependencies no longer had to block every otherwise valid child.
- Used player alias cell/location events and game-time callbacks to service the
  controller. Kept startup quests, aliases, FormIDs, and SEQ identities.
- Added optional logging, diagnostic globals, one-shot status, and initialization
  detail without normal-play popups. Schema advanced to 4 after reconciliation.
- Fault-injection tests demonstrated code paths, not actual native-call results.
  Tsoxer's engine diagnostics established running startup, a selected population,
  resolved roads/pool, and stage 8/reason 12 with no active children.

v0.2.3 — 11-15-2026
Direct road package targets and arrival tracing
- Distinguished 18 public roads from six private per-slot roaming markers.
  The private marker dependency could block arrivals before actor selection even
  when every road was resolved. Why those handles failed in Skyrim was unproven.
- Removed private-marker dependence from arrival and daytime movement. Added
  36 static walk/run Travel packages for the existing 18 roads, plus a short
  actor-relative Sandbox package. Old markers and FormIDs remained for saves.
- Preflighted road identity and actual pause/walk/run package forms before
  enabling. Preserved disabled-reference placement and repeated safety checks.
- Added precise per-slot dependency/lookup diagnostics and retained the lifecycle,
  randomization, startup, watchdog, and conservative removal systems.
- Schema advanced to 5. Saved appearance/reference identities were retained;
  migration refreshed package state without moving active children.
- Skyrim subsequently reported schema 5, stage 8/reason 0, population 5,
  enabled/tracked 0, pool 36/36, roads 18/18, and literally uninitialized arrays.
  Empty actor/destination fields did not establish that no attempt had occurred.

v0.2.4 — 11-15-2026
Array storage and silent-return repair
- Investigated suspect None-to-array CAST instructions followed by ARRAYCREATE
  into reused temporaries. The precise historical runtime compiler failure was
  not proven by a Papyrus log and was not presented as an established engine fact.
- Replaced array/None comparisons with boolean presence checks. Patched the
  Skyrim Caprica allocation path to reserve distinct long-lived temporaries,
  preventing allocation destinations from inheriting stale values or casts.
- Independently inspected all 30 setup allocations and the diagnostic allocation
  for types, lengths, distinct destinations, and failure guards. No None-to-array
  CAST pattern remained. A failed allocation could not commit the schema.
- Confirmed and fixed ReferenceInUse(None) matching empty resident slots. Added
  actor readback validation and explicit missing/duplicate-reference diagnostics.
- Runtime pool/road counts now reflect stored assignments, with resolved inputs
  shown separately. Added storage readiness/failure detail and reason 30/31 for
  allocation/shape and binding-readback failures. Recorded slot/actor/road progress.
- Retained valid arrays and repaired only missing or wrongly sized storage.
  Schema 6 committed after validation and reconciliation. Retained all 140 prior
  record identities, actors, packages, aliases, properties, and saved field types.
- Fault-aware tests covered allocation/readback failure, typed upgrades, skipped
  days, and the reported runtime-state shape; these remained mocked engine tests.
- Tsoxer subsequently confirmed working 3–6 populations, independent roaming,
  appearance variation, inn travel, and safe removal on old and pre-mod saves.
- New release filenames dropped the -MO2 suffix; historical filenames remained.

v0.5.1 — 11-16-2026
Worker transitions and native village interior travel

Evidence at release
- Reason 14 identified loaded/same-world exterior placement deferral. Stage 16 /
  reason 1 identified a busy callback. Windhelm's per-slot 23 described a previous
  captured-cycle/daytime mismatch; it was not the current reason or a lookup code.
- v0.5.0 retained all major-city payloads after rebasing and all seven old PEX
  binaries. Inspection found no static master-index collision, bad parent group,
  startup SEQ omission, or cross-city binding. This did not prove identical
  runtime behavior. Ten extra workers increased shared scheduler activity;
  engine queue pressure was not profiled and was not established as the cause.
- Old PEX allowed a busy transition's short retry to be overwritten by the
  finishing worker's longer PlanNext timer. Controlled interleavings reproduced
  this in both v0.4.1 and v0.5.0; it was not a newly introduced defect by itself.
- Whiterun yielded before claiming its processing lock and released ownership
  before snapshot/scheduling completed. Its cached safeRoads values could veto
  a newly safe indoor opportunity. These weaknesses also predated v0.5.0.
- All 34 Phase 3 night goals used Sandbox01C254 without a separate Travel step.
  InCell goals were valid constraints but not proof of observable door passage.

Corrections
- Added one Bool transitionPending and one Int lastWorkerStage to each of four
  controller types, retaining every existing saved variable/property/signature.
  Transition notifications arriving while busy survived the finishing worker's
  normal scheduling. A conditional 0.1-second retry used the existing timer.
- Whiterun claimed ownership before Status(2), retained it through scheduling,
  checked its epoch after snapshots, and used current SafeArrival checks.
  Preserved safeRoads for saves and retained the original visibility rules.
- Added optional status detail for last non-busy stage, pending transition, and
  lease remaining. Per-slot 23 traces included captured/current cycles and hour.
  Normal play gained no unsolicited diagnostic messages.
- Added 34 native Travel016FAA packages before the unchanged night sandboxes,
  one clocked and one per slot for each village. They targeted the same interior
  CELL, required GetInCell == 0, and ceased to apply after entry. Native AI then
  selected the existing sandbox. No scripted door movement or visible teleport.
- All 1,837 prior IDs remained. Added 34 packages and MB_RepairBuild = 501;
  total 1,872 records. Only 100 existing village NPC package lists changed.
  Retained 190 appearance bases, 760 actors, all clocks, roads, destinations,
  population ranges, quests, aliases, bindings, masters, and the 80-byte SEQ.
- Recompiled four controller PEX files; five alias/watchdog PEX stayed identical.
  Retained schemas 6/7 and migration identities, without resetting quests/actors.
  Executing controller diagnostic stamps identified 501; phase globals retained
  their historical values. Skaal's availability condition remained unchanged.

Validation and subsequent testing
- Independent ESP/VMAD/PEX checks verified the allowed record diff, master/group
  handling, package targets/conditions, and saved storage. Compilation succeeded
  with 24 inherited unused-field warnings. All 30 typed setup allocations per
  controller retained distinct destinations, without None-to-array CASTs.
- Five actual-PEX mock groups covered controlled interleavings, 1,140 settlement-
  days, ten appearances, all 19 population ranges, typed v0.4.1/v0.5.0 upgrades,
  saved array identity, watched retirement, skipped days, and fault recovery.
  Native callbacks, placement, geometry, and door results remained mocked.
- At publication, restored major-city reliability and native door traversal
  still required gameplay testing. The complete cause of the apparent v0.5.0
  engine regression was not established and was not retrospectively proven.
- Tsoxer initially observed absent populations in Whiterun and Morthal again,
  but later saw successful activation in both. Whiterun children were present
  after an extended daytime indoor stay; that observation did not measure the
  exact activation time. Delayed/inconsistent activation remained a known behavior.
- Tsoxer individually confirmed daytime spawning in all ten Phase 3 settlements
  and observed nighttime entry in multiple cases, including visible travel into
  Frostfruit Inn in Rorikstead. This was not exhaustive all-night/multi-day testing.
- After further gameplay testing, Tsoxer accepted v0.5.1 as the working baseline
  for public release. Historical failure reports remain part of the record.

v1.0.0 — 11-16-2026
First official free public release
- Promoted the accepted v0.5.1 gameplay implementation directly to v1.0.0.
  Cancelled v0.5.2 investigation/development; no v0.5.2 build was released and
  no proposed inn-spawning fallback was implemented.
- Reorganized the public README with features, all 19 populations/destinations,
  installation, requirements, scheduling expectations, compatibility, performance,
  and save/uninstallation information. Cleaned the cumulative development history
  while preserving dates, meaningful technical fixes, regressions, and milestones.
- At Tsoxer's request, updated all nine scripts' current diagnostic/log version
  strings to v1.0.0. Updated only diagnostic WriteDiagnostic stamp constants
  from 501 to 1000. Recompiled with the unchanged patched Skyrim compiler.
- Updated the ESP description and 58 current diagnostic/build global defaults.
  Those globals do not control migration or AI package conditions. Historical
  phase globals, schema values, and every saved field/property type remain.
  Already-saved global values may persist; live controller stamps refresh on use.
- Independently compared every decoded PEX function: only 45 approved version
  constants/strings differ. All opcodes, branches, calls, locals, variables,
  signatures, properties, and typed array allocations match v0.5.1.
- Kept all 1,872 record identities and record/group headers. Apart from the
  description and display-only global values, record bytes are identical.
  All NPCs, references, AI packages, quests, bindings, schedules, populations,
  settlement data, and the startup SEQ retain the baseline implementation.
- No gameplay repair, optimization, architecture change, new settlement,
  dependency, asset, or migration was introduced. The final runtime files are
  not byte-identical because of these explicitly authorized cosmetic changes.
- Final static checks and fault-aware compiled-PEX mock tests pass. Public
  performance assessment is moderate Papyrus overhead with localized native AI
  demand; no FPS, runtime latency, memory, or large-load-order benchmark exists.
- Existing activation delays remain documented. A non-blocking Whiterun recovery
  edge case was identified: an externally disabled current-day resident can leave
  a slot empty until the next daily cycle. It was not changed in this label-only
  release and was not established as the cause of earlier reported delays.
- Final archive contains the ESP, nine compiled PEX, startup SEQ, one README,
  and this complete cumulative changelog. No proprietary assets or development
  tooling are included. The final v1.0.0 package was not separately run in Skyrim
  in the cloud; the gameplay evidence is Tsoxer's accepted v0.5.1 testing.

v1.1.0 — 11-16-2026
Vanilla human child race variety
- Added genuine Imperial, Breton and Redguard child races alongside the existing
  Nord children. Each race supports male/female appearances and all five existing
  red, blue, green, grey and yellow child outfits: 40 combinations per settlement.
- Race is an independent RandomInt(1,4) draw (25% each), gender an independent
  RandomInt(1,2) draw (50% each), and clothing retains RandomInt(0,4) (20% each).
  All races are eligible in all 19 settlements; no city-specific weighting.
- Retained Nord donors Lars/Dorthe. New donors: Imperial Francois/Mila, Breton
  Blaise/Erith and Redguard Alesan/Braith. Corresponding child RACE records and
  donor gender identities were checked against public game-record/reference data.
- As authorized, new variants inherit their appropriate vanilla donors' normal
  child stats and template defaults. Exact Nord-only non-appearance equivalence
  is not claimed. Donor scripts, factions, inventory and AI package lists are not
  inherited; each new record copies the corresponding settlement's More Brats
  packages, factions, keys, name and outfit unchanged.
- Appended 570 NPC bases and 2,280 initially disabled persistent actor references.
  The complete fixed pool now contains 3,040 references and 760 NPC bases. The
  normal combined active daily target remains 42–76, with all 19 ranges intact.
- Preserved all 1,872 existing FormIDs, 190 original Nord NPC bases, 760 original
  placed actors, all 472 AI packages, roads, inn/cell goals, factions and lists.
  Added three appearance-reference bindings to each of 19 existing quests; alias
  data, startup settings and SEQ bytes are unchanged. Total: 4,722 records.
- Kept the legacy Nord pool/indices and saved variant values 0–9 unchanged.
  Three separate actor-reference arrays and three orphan-observation arrays per
  controller avoid Papyrus's 128-entry array limit. New variant indices 10–39
  map to appended reusable references; no unlimited spawning or new controller.
- Extended only appearance storage validation/binding, lookup/indexing, selection,
  and existing pool bookkeeping/counting to cover the additions. Missing saved
  new properties recover through stable local IDs. Existing valid arrays and
  active actors are retained, with schemas 6/7 and old property/field types intact.
- Spawning safety tests, road selection, native placement/enabling sequence,
  daytime roaming, run/pause timing, pathfinding goals, schedules, retirement
  observations, callbacks, leases and transition handling retain v1.0.0 logic.
  Phase 3's Travel-to-Sandbox packages are byte-identical. No unrelated bug fix.
- Recompiled nine scripts: four require appearance-pool changes; five aliases/
  watchdog change only version strings. Live labels identify v1.1.0 and current
  diagnostic stamps use 1100; historical phase values and schemas are unchanged.
- Independent ESP/VMAD/PEX readers and a strict baseline diff check old records,
  new race/template/outfit pairs, property bindings, internal links and array
  allocation bytecode. All arrays stay at or below 90 entries individually.
- Compiled-PEX mock tests cover 1,900 settlement-days, all population ranges,
  all 3,040 slot/variant mappings, 57 typed old-state upgrade cases, faults,
  missing added references, the Skaal availability gate and independent RNG draws.
  Sampling is approximate; the algorithm's probabilities are not forced quotas.
- The same active NPC counts, AI packages, scripts/instances and timers remain.
  Persistent storage and pool-scan work increase because four appearance pools
  are examined. No claim of unchanged CPU/RAM/save size or measured performance.
- Public metadata confirms male/female models and all four child-race entries
  for the five existing torso outfits and shoes. Traits inheritance reuses
  Bethesda appearances; no custom races, FaceGen, models, textures or voices
  are supplied. Requirements remain the same three official masters; no SKSE,
  Address Library, SPID, external framework or paid Anniversary content.
- Source/API/reference checks are not a Skyrim rendering, native pathfinding,
  real ESS migration or performance test. v1.1.0 still needs Tsoxer's playtest,
  particularly new heads/skin tones/outfits and an upgrade with active children.
  Existing activation delays and earlier known limitations remain unchanged.
- Historical downloads and all v0.1–v1.0.0 changelog entries remain intact.
